## Subject

Purge personal information from history (paths; the commit address is allowed since 2026-10-26)

## Letter

🔒 **Owner: purge personal information from git history, as loader-dotnet did — "a necessary thing for
security"; the other projects follow.** Template: loader-dotnet `cmem/overview.md:150-164` (find with `git
grep` over every commit; `git filter-branch`; verify zero hits in every tree, message and header; force-push
**with lease**; prune; record the old→new hash map). What to purge: (a) personal drive paths and tracked tool
settings (letter H18's list); (b) ~~the owner's personal address as author/committer → noreply~~ **WITHDRAWN
2026-10-26 (owner): the maintainer contact email is the one official exception and it covers commit
author/committer metadata too** — the address on existing commits stays, no `user.email` change is required,
and a purge rewrites PATHS (and any other personal information), not the address. Repos that already rewrote
it to noreply (-dotnet, rsxtk, wazmrt, wasmtk, -c) leave it as it is. **Cross-repo hazards this letter exists
for:** (1) **binaryang, wabt-ts, binaryen-ts carry upstream wabt/binaryen history** with hundreds of
third-party contributors — rewrite ONLY the owner's address (a mailmap-style match), never "all emails";
upstream authorship is theirs and already public. (2) **Every ref:** branches AND tags (`--tag-name-filter cat
-- --all`; binaryang 375 branches / 21 tags, wasmtk 77 / 77, wasmrt 17 tags, loader-js 10). (3) **Published
releases keep the OLD hash forever** — JSR/npm provenance (Rekor), crates.io `.cargo_vcs_info.json`, NuGet
SourceLink; nothing can change them. Record the map tag by tag. (4) **Keep every TAGGED tree byte-identical**
— change metadata only on tagged commits; loader-go especially: Go's checksum DB hashes the module CONTENT, so
a changed tagged tree breaks `go get` for every user (its trees have no path hits — rewrite email only). (5)
**Hashes cross repos**: wasmtk's `f50c8e4` is the H7 fixture stamp in loader-js `tests/fixtures.json` and
loader-dart's copy; this workspace's letters cite dozens of shas. **Order:** wasmtk first, BEFORE pushing its
131 unpushed commits (one push, already clean), then loader-js re-stamps fixtures from a PUSHED commit (closes
drift X8), then the ports copy them; the workspace updates its citations from each repo's published map. (6)
**Other clones re-push the old history**: wasmtk's `upstream/binaryang`, wabt-ts's nested clones, scratch
copies — re-clone after; never push from an old clone. (7) **GitHub still serves old commits by hash** until
its GC, and forks/PR refs keep them; a full purge is a GitHub Support request (owner). (8) No host Python:
`git filter-repo` needs Python — use `filter-branch` as -dotnet did, or pixi's Python. (9) Run H16's `gc
--prune=now` + `maintenance.strategy gc` right after (the prune is part of the purge). (10) When recording the
purge, do not write the personal address — "the owner's personal address". (11) **Leave the maintainer contact
email in package manifests alone** (owner exception, 2026-10-23, working-rules § Records): a publishing
project's registry maintainer/author field may carry one contact email — present today in loader-py
`pyproject.toml` and loader-jvm `build.gradle.kts`; purge commit METADATA, not that field. rsxtk's
`Cargo.toml` carries one too, and rsxtk DOES publish (crates.io `rsxtk`, 34 versions — corrected 2026-10-23
from "publishes nowhere", caught by wasmtk), so it is allowed.
