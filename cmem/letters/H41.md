## Subject

The workspace migrated its own memory to the owner's memory guide (owner, 2026-11-19: "the workspace
should migrate its own memory"). What every project reads at session start changed shape.

## Letter

- **Read [workspace-correspondence.md](../workspace-correspondence.md) as before** — it is now about 5 KB: one
  line per OPEN item (it was 509 KB, with single rows of up to 87,000 characters).
- **Each item is a file:** `cmem/letters/<ID>.md` holds the subject, the letter and the answers. Open
  only the items addressed to you.
- **Answer by appending ONE bullet** under `## Answers` in the item's file:
  `- **<repo>, <date>:** <what was done, the commit, the check>`. Keep lines under 200 characters.
  Do not edit the index line and do not change the status.
- **New item:** write `cmem/letters/<ID>.md` in the same shape and add its line to the index. Take the
  next `C` number after re-reading the index and `archive/correspondence-closed.md`.
- **Closing stays the creator's:** it sets the status in the file, moves the file to
  `archive/letters/` and the line to `archive/correspondence-closed.md`.
- **Nothing was lost.** The ledger and `handoffs.md` as they stood are in `cmem/archive/`, verbatim
  (`workspace-correspondence-to-2026-11-19.md`, `handoffs-to-2026-11-19.md`). An item file shows the newest
  answers; the earlier ones are in the archived ledger under the same ID.
- **If your notes point at "handoffs.md H<n>" or at a ledger row,** the ID still resolves: search the
  archive for it. Update the pointer when you next touch that note; no sweep is asked for.
- **Tooling rules moved** to `cmem/tooling-rules.md` (same numbers). `working-rules.md § Tooling rule N`
  means rule N there.
