# H44: "push" no longer merges; "merge to main" is its own word

- Status: open
- Date: 2026-11-27
- From: workspace
- To: every project

## Subject

Owner, 2026-11-27, first in a zailc session (letter C54) and then confirmed for every project in
the workspace session: "pushing should mean push to the branch on github. 'merge to main' should
merge the branch to main and prune the branch afterwards." This amends the owner's words of
2026-11-10 (letter H34). The rule is Tooling rule 12 in `../workspace/cmem/tooling-rules.md`.

## Letter

**The four words now.** Each includes the one before; none goes further than its own word.

- **"commit"** — unchanged: update the project memory files, then commit to the working branch.
  Nothing reaches GitHub.
- **"push"** — "commit", then push the working branch to ITS OWN branch on GitHub and read it back
  with `git ls-remote`. Nothing is merged; `main` does not change.
- **"merge to main"** — "push", then, in this order (owner: "the wip branch is merged to main, then
  main is pushed to github, then the branch is deleted in that order"):
  1. merge the work branch into `main`;
  2. push `main` to GitHub and read it back;
  3. delete the work branch on GitHub, then locally with `git branch -d`, which refuses an unmerged
     branch. Never `-D`.
- **"release"** — "merge to main" when the work is on a work branch, then the release process
  (Tooling rule 11). The release runs from `main`.

**What is deleted, and what is not.** Only the work branch that "merge to main" has just merged.
Release branches and review branches kept on GitHub as a record stay (owner: "no. just the
unmerged wip branches"). Do not clear old branches on the strength of this letter; that takes the
owner's word in your own session.

**On `main` already?** "push" pushes `main`; "merge to main" has nothing to merge or delete.

**Asked of each project:**

1. Replace the "Owner commands" section the workspace wrote on 2026-11-10 (in your
   `cmem/working-rules.md`, `cmem/INDEX.md` or `cmem/conventions.md`) with the four words above.
2. If a script, a gate or a note of yours says that "push" merges into `main`, change it.
3. Answer below with the commit, and name any place where your project differs and why.

zailc already follows this (its DD-50 and DD-51); it only needs to check its record against the
order in "merge to main" and the limit on what is deleted.
