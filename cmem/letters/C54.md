## Subject

On the owner's direction (2026-11-27: "We need to add these rules to the workspace for clarity"). The
owner redefined "push" and added "merge to main" in a zailc session; Tooling rule 12 still says
"push" merges into `main`. The workspace owns rule 12, so zailc hands the words over here.

## Letter

**The question that started it** (owner, 2026-11-27): "When we have a wip branch, is it the commit
that changes the wip branch on github or the push?" The answer: only a push changes GitHub; a commit
never does. Under rule 12 as written, an unfinished branch never reached GitHub on its own: "push"
merged it first.

**The owner's words, the same day:**

- "any branches on this machine should be deleted as they hold old information on this project"
- "pushing should mean push to the branch on github. 'merge to main' should merge the branch to main
  and prune the branch afterwards."

**As zailc recorded them** (`../zailc/cmem/working-rules.md` § Owner commands; decisions DD-50 and
DD-51 in `../zailc/cmem/design-decisions.md`):

- **"commit"** — unchanged: update the project memory files, then commit to the working branch.
  Nothing reaches GitHub.
- **"push"** — "commit", then push the working branch to ITS branch on GitHub and read it back with
  `git ls-remote`. Nothing is merged; `main` does not change.
- **"merge to main"** — "push", then merge the branch into `main` with `--no-ff`, push `main` and
  read it back, then prune the branch: delete it on GitHub, then locally (`git branch -d`, which
  refuses an unmerged branch). `main` is the only long-lived branch.
- **"release"** — "merge to main", then the release process (rule 11). Was: "push", then the release.
- **Branches:** merged branches are not kept (this replaces zailc's "keep the branches",
  2026-10-08). The `--no-ff` merge commit on `main` is the record of the work.

**Two readings in that record are zailc's, not the owner's words — confirm them with the owner:**
(1) "merge to main" also PUSHES `main` before pruning, so a branch is never deleted from GitHub
while its work exists nowhere else there; (2) "release" starts from "merge to main", because the
release runs from `main`.

**Done in zailc on 2026-11-27, on the owner's word:** the 50 merged local branches deleted, then
the six merged branches on GitHub (each checked an ancestor of `origin/main` first); `main` is the
only branch in both places. The record above is in zailc's working tree, not yet committed.

**Asked of the workspace:** amend Tooling rule 12 with these words if the owner confirms they hold
for every project, and send the change to the projects as a letter; or record that they are zailc's
alone. Until then zailc follows them and no other project is affected.
