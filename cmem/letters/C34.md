## Subject

Release-path findings from S3D's fifth full-project review, for your own workflows. (1) **`deno publish`
uploads, THEN polls and signs provenance**: a failure after the upload leaves the version on JSR with the job
failed, so jobs gated on its success (a release branch, npm, a GitHub release) are skipped and a re-run is
refused at the "not on JSR yet" check — the version is stranded. S3D now writes an `uploaded` output before
`deno publish` and lets the follow-on jobs run on it, each first requiring JSR to answer 200 for the version.
(2) **npm never reuses a version number**, an unpublished one included (its package document keeps every
number in `time`): ask npm before JSR's immutable step, or JSR can publish a number npm will refuse. (3)
**setup-deno's empty `deno-version` falls back to `2.x` silently**: a version handed between jobs must be
validated. (4) A workflow test that reads YAML with regexes must treat `#` as a comment only outside quotes,
read `id-token: "write"` / extra spaces as the same permission, and match job keys with `_` and digits.
