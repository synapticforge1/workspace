## Letter

**1. The machine must be x86_64 Linux.** The port's check runs upstream's sarcasm under the `minilute`
interpreter from Fil-C 0.687's `linux-x86_64` release (`../zilc/tools/sarcasm/check-stages.ts` line 23,
`FILC_PREBUILT_TREE/pizfix/bin/minilute`), and every zilc tool refuses to start outside Linux
(`../zilc/tools/lib/tool.ts`, `linuxOnly`).
- A Linux guest on the Intel Mac: suitable.
- A Linux guest on the arm64 Mac is arm64 Linux: `minilute` does not run natively. Parallels' Rosetta for
  Linux might run it; untested, and an emulated oracle is not wanted for a byte-identity check.
- macOS itself: no.
- Check: `uname -m` prints `x86_64` in the guest.

**2. One-time setup in that guest** (far less than the dev machine held: no Fil-C source clone, no
patched-clang build, no Fil-C suite tree):
- Bun, then from the repo: `bun tools/p1/setup-wsl.ts` (`../zilc/tools/README.md` steps 1–2; the name says
  WSL, the tool runs on any Linux). It installs Zig 0.15.2, the Fil-C 0.687 release (with `minilute` and
  upstream's sarcasm `.luau` modules under `pizfix/lib/sarcasm/`) and patchelf, each checked against a
  recorded sha256.
- Fil-C's source package in Zig's global cache, `~/.cache/zig/p/<hash>`, the hash from
  `../zilc/build.zig.zon` (`.filc`, GitHub `llvm-project-deluge` at `e7947f0`). The first `zig build` that
  reads it fetches it; the harness takes its 1,431 test `.s` files from there
  (`../zilc/tools/lib/tool.ts`, `filcPackageDir`). Do not move `ZIG_GLOBAL_CACHE_DIR` away from it.
- Network access to GitHub; several GB of downloads.
- Check: `bun tools/sarcasm/check-stages.ts` on zilc's `origin/main` prints `OK: every stage equal to
  upstream's` (as of 2026-11-25: xframe 214,551 log lines, 0 differ; every stage 0 differ).

**3. Run from a clone on the guest's own disk, not from the drive** (`machine-setup.md` § Work on a copy):
zilc's tools already keep Zig's caches in the Linux home (`zigCacheArgs`), but the build outputs and the
harness's work folder must not sit on exFAT.

**4. What a clone does not carry.** Checkpoint 10 is partial and UNCOMMITTED in the drive's working tree
(`../zilc/cmem/STATE.md` § Now): `src/sarcasm/x86_64_frame_sbranges.zig`, four
`tests/sarcasm/frame-branches/sbranges-*.s`, and edits to `src/sarcasm/x86_64_frame.zig`,
`tools/sarcasm/check-stages.ts`, `tools/sarcasm/stage-check.zig`; the stopped agent's records are in the
gitignored `../zilc/cmem/local/port-cp10-partial/`. Either copy those by hand from the drive, or the owner
has zilc commit them to a separate work-in-progress branch first (not `main`). zilc's rebuild notes for
everything left behind are in its gitignored `cmem/local/environment.md`.
