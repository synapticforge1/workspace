## Subject

🔒 The TypeScript projects test per ENGINE, not per platform (owner, 2026-11-19: "that way we do not over test
something"): one module named `host` holds every OS call, a gate keeps other files off the runtime's file /
path / process APIs, an on-demand `--self-check` lives in `host`, OS-specific testing concerns `host` alone
and only when it changes, arm64 rows read `runtime`

## Letter

🔒 **Owner, 2026-11-19: "Let's make the changes for the typescript projects I noted, that way we do not over
test something."** Full text: workspace `platforms.md` § "The TypeScript projects". **(1) Test what you
compute per ENGINE, on one machine** — V8 (Node, Deno), JavaScriptCore (Bun); LeptonPad: the browser engines —
not per platform, and no separate arm64 run: the runtimes hide the OS and the CPU for pure TypeScript, and a
`.wasm` module is the same bytes everywhere. **(2) One module named `host`** (owner: "one module named the
same per project … all of the OS/platform specifics lives in one place"): every call that touches the system —
opening and writing files (never over an input, never half-written), temp files, paths, environment, starting
other programs — goes through it; add a scripted gate that fails when any file outside `host` imports the
runtime's file, path or process APIs. **(3) An on-demand self-check in `host`** (owner): `--self-check` tries
`host`'s operations on the machine it runs on and reports what fails; only when asked, and it cleans up after
itself. **(4) OS-specific testing concerns `host` alone:** its tests run on an OS when that machine is at hand
and again only when `host` or the pinned runtime changes; a release that changed neither carries the last
result forward; nothing waits for it (H37's "Tested on" rule) — an OS not yet run is `pending`, and the tool
is checked there when it is met, by the self-check. **(5) Your matrix** (`cmem/platforms.md`) uses a sixth
status, `runtime`, for a platform covered by the runtime and by `host`'s result for its OS (your arm64 rows).

**wasmtk** — files and the compilers you start are `host`; your existing I/O layer is the start of it.

reports' digests across OSes. **LeptonPad** — the app per browser engine; its server side runs on Linux only. Moving calls into `host` is a refactor: do it under your gate, with the reference results
unchanged. Answer with your commits (the module, the gate, the self-check, the matrix). · **🔒 Confirmed by
