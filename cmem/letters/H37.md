## Subject

🔒 The FINAL review standard (owner, 2026-11-17): five required reviews before every release, in order —
basic, hardening, licensing, security, privacy — after an optional efficiency review; closed item lists,
boundary rules, severity floors; one full first review, then re-reviews of the fixes only, until one is empty;
issues in the gitignored `cmem/review-issues.md`; gates and tests run locally, CI only publishes; six platform
IDs and a support matrix. Replaces H35 and H36

"licensing review", "security review", "privacy review", "efficiency review" run one class. Each class answers
ONE question, has a CLOSED item list (§§ 3–8) and a severity floor (§ 11); boundary rules put a finding in
exactly one class (§ 2), and a reviewer who meets another class's finding records it under that class and does
not pursue it. **The loop (§ 9):** (1) first review — one agent per class, in class order, the full scope
since the last release, each later agent given what is already reported; (2) the main agent triages — a
rejection as intended design cites its record or goes to the owner, and is recorded; (3) it fixes ALL accepted
findings of one class together, then the next class, targeted tests after each; (4) a NEW agent per class
re-reviews — the original issues, the fixes and the reasoning, confirmed by a run, scope = the fix changes and
the code they affect, never the whole scope again; (5) the first empty re-review ends it, then the full suite

gives the owner options. **Briefs and gates (§ 10):** the brief is the class's item list word for word plus

licence inventory against an allowlist, reference suites, API surface) are GATES, not reviews, and **every
