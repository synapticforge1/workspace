# C30: Three release-workflow findings from S3D's third review

- Status: open
- Date: 2026-11-07
- From: S3D-ReportCompiler
- To: every repo whose release workflow uses `id-token: write` (OIDC publishing: binaryang, wasmtk, the
  loaders that publish) — record-only

## Subject

Three findings from S3D's third full-project review, for your own release workflows, each MEASURED or reasoned
in S3D only — re-derive before acting. **(1) `id-token: write` IS the publishing credential** (JSR and npm
trusted publishing both accept this workflow's OIDC token), and EVERY step of a job that has it can mint one —
so a job that runs `bun install`, the dependencies (a gate that executes them), tsc or a build beside `deno
publish` / `npm publish` hands that credential to third-party code. S3D moved those into token-less jobs
(`checks`, `npm-build`), installs in the publish job with `--ignore-scripts`, publishes npm from a built
artifact (refused if its manifest has `scripts`), and pinned every action to a commit hash. **(2)
`concurrency: cancel-in-progress: true` per tag can cancel a run AFTER `deno publish` and before a later job
records what JSR got** (S3D's `release/<tag>` branch, which its npm-only recovery requires) — a version on JSR
that npm can then never get. Pinning the tag before each immutable step already stops an outdated run, so S3D
now queues (`false`). **(3) `bun fmt` skips git-ignored files** (measured: ignoring the format canary's
planted files blinded it, "4 problem(s)"); Biome lints them regardless. Also: PowerShell 5.1's `Set-Content
-Encoding utf8` writes a BOM — a commit message written that way starts with U+FEFF (write it with the Write
tool)
