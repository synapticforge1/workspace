# cmem — workspace memory for the wasmExamples siblings

**Scope** (counted 2026-10-27). Twenty sibling projects — fifteen WebAssembly git repos plus the
orphan `lisp-wat_interpreter` (no `.git`), and LeptonPad, S3D-ReportCompiler, zailc and zilc since
2026-10-26 — each git repo with its own `cmem/`. Removed: wabt-ts and binaryen-ts (2026-10-26),
ub-cosmic (2026-10-27, folder and GitHub repo deleted — owner). This layer holds what is common
(the rules every repo has independently paid for), what crosses repo boundaries (contracts, pins,
the shared corpus), and the map of who consumes whom. **It never overrides a repo's own memory**; a
repo's `working-rules.md` / INDEX policy governs inside that repo. When this file and a repo's memory
disagree, the repo's file is the older claim and this one is the reconciliation — but MEASURE before
choosing either.

🔒 **Role (owner, 2026-09-20): this memory holds the reins on divergence between projects, and the
workspace session is the reviewer, reporter and communicator of issues arising between them**, so
each repo stays on task and the common goals are produced. Every place two repos implement the
same thing is a row in [divergences.md](divergences.md) with a class and an exit condition; what a
repo needs to know is a letter in [handoffs.md](handoffs.md), which repo sessions PULL at start.
Those two files are the memory a session in ANY repo may write to; the sibling-boundary rule
covers repos, not this ledger.

**Written 2026-09-20**; every number in these files carries that date unless it names another.
Refresh history (2026-10-22, 10-26, 10-27, 10-28, 10-30, 11-05, 11-07, 11-08, 11-09, 11-10, 11-12): [handoffs.md](handoffs.md) § "Refresh history". The folder is `synapticforge1` (was `wasmExamples`; 🔒 ★ stamp — letter H27, X18).

## Policy for this directory (the rules the siblings' drift taught)

- **This index stays one line per file.** Session bootstrap is this file plus the root pointer, and
  must stay under about 10 KB. Status narrative never goes here; it goes in
  [open-work.md](open-work.md), once.
- **Method in [best-practices.md](best-practices.md), findings in the topic file.** A rule is one bold
  sentence, the incident that paid for it, and its origin tag.
- **Working memory, not an archive.** Completed work is summarized with a pointer to where the full
  text lives (a commit, or a sibling's file). A summary without a pointer is a loss.
- **A number is a claim with a date.** Re-derive before acting on it.
- **Nothing private in these files** except under `local/`, which is machine-only by convention.
  **The path rule applies here too** (owner, 2026-10-23), although this folder is never published:
  repo sessions copy text out of the letters and tables, so nothing outside `local/` — `cmem/*.md`,
  `tools/`, `../CLAUDE.md` — carries a path that records this machine's layout. Use paths relative
  to the workspace (`../wasmtk/…`, `tools/…`), placeholders (`<workspace>`, `<scratchpad>`), or a
  script that derives its location (`tools/assembler-parity/measure.ts` resolves its root from
  `import.meta.dir` since 2026-10-23). The test is "is it machine-specific?" — a convention path such
  as `C:\zig-cache\wazmrt` is fine; the real machine paths live in `local/environment.md`.
  🔒 Workspace-wide (owner, 2026-10-22): **no secrets or personal information are ever made
  public**; committed `cmem/` is fine as long as it displays none — [working-rules.md](working-rules.md) § Records.
- **Never run a formatter on `cmem/`.**
- **Renaming a heading is a breaking change** — grep every sibling for the `§` citation first.

## Triggers (binding, in any repo under this folder)

1. **"update the project memory"** — revise the matching topic file in the repo you are working in,
   refresh its index pointer, absolute dates, update rather than duplicate. Then AUDIT: grep the old
   values across that repo's `cmem/`, `README.md` and `CLAUDE.md`; when two files disagree, measure.
   Sync `README.md` only where the change is user-relevant. Cross-repo lessons come HERE as well.
2. **"look for code issues"** — audit tested AND untested paths for workarounds, dead code
   (grep-verified), bugs, and silent fall-throughs (the worst class); fan out read-only investigators
   per category; report `file:line` + severity; fix the safe ones; diff OUTPUT, not exit codes.
3. **"coordinate"** — run the sibling contract protocol ([contracts.md](contracts.md) § "Runtime
   interop"): read the contract first, verify rows by RUNNING both binaries, record in your own copy,
   never write the sibling's tree. An order to confer, never a licence to write.
4. **"reconcile"** (workspace level) — take one row of [drift-register.md](drift-register.md),
   measure which side is true, fix it in the repo that owns it, close the row with the commit.
5. **"divergence"** (workspace level, binding on every repo session) — a cross-repo difference
   found in any session is filed in [divergences.md](divergences.md) in that session: what is
   implemented where, class (or UNMEASURED), what closes it. A difference is not done until it has
   a row with a class; "both work" is not a class. Read DESIGN rows before matching a sibling.
6. **Regression gate** — a CHANGE to `src/` triggers the repo's full gate, run on the committed tree
   after the last edit, reading every exit code. A batch with no `src/` change does not.
7. **Correspondence before new work** (🔒 owner, 2026-10-26, binding on every repo) — before
   starting a new work item, read [workspace-correspondence.md](workspace-correspondence.md) for
   every open row addressed to you or touching what you will change; handle or record the
   conflict first. Any project adds rows; only the item's creator verifies and closes it.

## Outside cmem

- `../tools/<check>/` — the reviewer's measurement scripts and their dated outputs, one folder per
  check (`assembler-parity/` since 2026-09-20). A check that lives only in a scratchpad is lost.
  Run with `bun <script>.ts` (ported from Deno 2026-10-22; binaryang's CLI is invoked as
  `bun main.ts`, same bytes as Deno on 21/21 sampled). Every run writes `corpus.json` (wasmtk HEAD
  + file-list hash), because the corpus is mostly wasmtk's gitignored build output.
- `../CLAUDE.md` — the root pointer, machine-local by nature (this folder is not a git repo).

## Reading order for someone new

1. This file, then [projects.md](projects.md) — what exists and how it connects.
2. [working-rules.md](working-rules.md) — how an increment is done anywhere here.
3. [best-practices.md](best-practices.md) § 1–3 before touching a test, a gate, or a producer/consumer pair.
4. The repo's own `cmem/INDEX.md` for the repo you are about to work in.
5. [goals.md](goals.md), [divergences.md](divergences.md) and [drift-register.md](drift-register.md)
   when planning — the first says where we are going, the second what must not silently fork on
   the way, the third what is already inconsistent in the records.
