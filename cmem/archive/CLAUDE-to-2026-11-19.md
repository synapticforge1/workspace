## Rules that bite in the first five minutes

- **Every repo's own `cmem/working-rules.md` (or INDEX policy) governs inside that repo.** The
  workspace rules in [`cmem/working-rules.md`](cmem/working-rules.md) are the common floor.
- **Nothing is ever written into a repo from a session working in another repo**, unless the owner
  directs that specific write. Draft the handoff in your own memory and hand it over.
- **Committed scripts kept for repeated use (anything that would be a shell script) use the repo
  language's own scripting mechanism, else Bun/TypeScript; a one-time script deleted after use may
  stay a shell script (still written with `Write`)**. A mechanism that must BUILD AN EXECUTABLE to
  run the script does not count (owner, 2026-10-22); a JVM `.jar` is allowed. So pixi's Python,
  `dart run` and Kotlin `.main.kts` qualify; Zig, Go, V, Rust, C and C# use Bun (C# was `.csx`
  2026-11-08 → 11-09, back to Bun by the owner, C42); the workspace uses Bun.
  A port replaces its TS original only after an output-diff proves them equivalent. Table:
  [`cmem/working-rules.md`](cmem/tooling-rules.md) rule 1 (owner, 2026-10-22). Deno only
  where JSR publishing needs it. No host Python. No committed shell scripts. No
  heredocs, ever, for any content, including commit messages** (`git commit -F <file>`). Content goes
  through `Write`/`Edit`. This owner rule outranks a session instruction to prefer Bash; say so when
  they conflict.
- 🔒 **No secrets or personal information are ever made public** (owner, 2026-10-22): no tokens,
  keys, passwords, emails, or **personal drive paths** (any path that records the owner's machine layout —
  `D:\Programs\…`, `C:\Users\…`, `J:\…`; use repo-relative paths or placeholders; a convention path
  that names nothing about one machine, like `C:\zig-cache\wazmrt`, is fine — the test is
  "machine-specific?", owner 2026-10-23) in any committed
  file, commit message, package or issue. **Exception (owner, 2026-10-23/26): one maintainer contact
  email** in the manifest field a language package registry reads, as the git commit
  author/committer address, and in ONE committed `cmem/` note that names the maintainer contact
  (every repo, owner 2026-10-26) — nowhere else.
  Committed `cmem/` is fine as long as it displays none; private facts go in the
  gitignored `cmem/local/`. Scan before committing memory; a leaked secret is rotated. Full rule:
  [`cmem/working-rules.md`](cmem/working-rules.md) § Records.
- 🔒 **No `gh` (owner, 2026-11-08), in CI too: check the repo instead** — `git ls-remote` and the
  repo's own files; in a workflow, GitHub's REST API from a Bun step with `GITHUB_TOKEN`; a GitHub
  web-UI task is an owner item. [`cmem/tooling-rules.md`](cmem/tooling-rules.md)
  rule 9.
- 🔒 **Every Bun-version notation is the latest installed Bun, always (owner, 2026-11-09)** — 1.4.4
  on Windows and WSL, measured 2026-11-09; pins, installers, Docker tags, `@types/bun` and the
  minimum supported Bun move at a repo's next session; a dated test result stays until that test is
  re-run. Tooling rule 10 (`cmem/tooling-rules.md`), letter H31.
- 🔒 **Releases, every project (owner, 2026-11-10; amended 2026-11-17): the checks run LOCALLY
  first (the review set and every gate, on every supported platform) → CI pushes the tag → the
  Release page from the tag → the publish to the registry** — CI only publishes, never the owner's
  machine; recorded in `cmem/release.md` § "Release History", newest first, with a summary of each.
  [`cmem/release-process.md`](cmem/release-process.md) §§ 5–8, Tooling rule 11 (`cmem/tooling-rules.md`), letter H33.
- 🔒 **The owner's words (2026-11-10), every project:** "commit" = update the project memory
  files, then commit to the working branch; "push" = commit, merge into `main`, push to GitHub;
  "release" = push, then the release process. Each includes the one before, none goes further.
  Tooling rule 12 (`cmem/tooling-rules.md`), letter H34.
- 🔒 **Reviews, every project — FINAL standard (owner, 2026-11-17):** five required reviews before
  every release, in order — **basic, hardening, licensing, security, privacy** — after an optional
  **efficiency** review; "review" runs all five, "<class> review" runs one. A closed item list and
  a severity floor per class; one full first review, then re-reviews of the fixes only, until one
  is empty; issues in the gitignored `cmem/review-issues.md`; gates and tests run locally.
  [`cmem/review-process.md`](cmem/review-process.md), Tooling rule 13 (`cmem/tooling-rules.md`), letter H37.
- 🔒 **Project memory, every project (owner, 2026-11-17):** a session reads `cmem/STATE.md` and
  `cmem/INDEX.md` (a router) first and opens other notes only when the task needs them; size
  limits (INDEX 3 KB, STATE 60 lines, a note 25 KB, a line 200 characters) held by
  `scripts/check-cmem.ts`; closed items go to `cmem/archive/`.
  [`cmem/memory-guide.md`](cmem/memory-guide.md), Tooling rule 14 (`cmem/tooling-rules.md`), letter H38.
- **A written number is a claim with a date.** Re-derive before quoting or acting on it.
- **Nothing is pushed, published, or tagged unless the owner says so.** The manifest version line
  ARMS a release in every Deno repo.
- Machine facts (drive quirks, installed oracles, paths) are in
  [`cmem/local/environment.md`](cmem/local/environment.md), never in a committed file.
